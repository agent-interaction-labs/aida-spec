# Governance

AIDA is an open specification developed under the Agent Interaction Labs organization.

## Principles

1. **Open process.** All specification development happens in the open on GitHub.
2. **Consensus-driven.** Changes require consensus among active contributors.
3. **Backward compatibility.** Breaking changes require a new specification version.
4. **Implementation-driven.** Specification changes should be accompanied by reference implementations.

## Roles

- **Maintainers:** Approve and merge specification changes.
- **Contributors:** Propose changes via pull requests.
- **Community:** Provide feedback via issues and discussions.

## Specification Lifecycle

1. **Draft:** Work-in-progress in `draft/` directories.
2. **Proposed:** Feature-complete, awaiting community review.
3. **Stable:** Published in a date-stamped directory (e.g., `2026-XX-XX/`).
4. **Deprecated:** Superseded by a newer version. Retained for reference.

## Changes

- Minor changes (clarifications, examples, schema refinements) → PR + one maintainer approval.
- Major changes (new layers, breaking schema changes, new mandatory features) → PR + consensus + implementation.

## Dispute Resolution

If consensus cannot be reached, the maintainers make a final decision. Decisions can be appealed via a written proposal with technical justification.

---

*This governance model will evolve as the project grows.*
